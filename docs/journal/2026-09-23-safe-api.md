# 2026-09-23: Safe `cujson` crate (task 06)

## Current State

- `crates/cujson/src/lib.rs` exposes `parse(&[u8])`, `parse_owned(Vec<u8>)`,
  `parse_lines(&[u8], LinesOptions)`, `parse_file(impl AsRef<Path>)`, and
  `cuda_info() -> Result<CudaInfo, Error>`. Without the `cuda` feature every
  parse function returns `Err(Error::CudaNotCompiled)` before touching any
  FFI declaration (`lib.rs:120-176`); with it, each checks input size first
  (`check_size`, `lib.rs:98-108`, rejecting `len == 0` as `EmptyInput` and
  `len >= MAX_INPUT_LEN` as `InputTooLarge`, mirroring
  `capi_standard.cu:26`'s `size >= INT32_MAX - 8` check) then calls into
  `crates/cujson/src/ffi.rs`
- `MAX_INPUT_LEN = i32::MAX as usize - 8` (`lib.rs:59-64`)
- `LinesOptions::default().chunk_bytes == 256 * 1024 * 1024` — matches
  upstream's own default (`vendor/cuJSON/main_jsonlines_chunksize_MB.cu:16`,
  `size_t maxChunkSizeMB = 256;`). `cujson_parse_lines` itself treats
  `chunk_bytes == 0` as "one chunk covering the whole input"
  (`crates/cujson-sys/cuda/capi_lines.cu:73`), documented on the
  `LinesOptions::chunk_bytes` field (`lib.rs:70-76`)
- `crates/cujson/src/ffi.rs`: every FFI call (`parse_standard`,
  `parse_lines`, `cuda_info`) takes `GPU_LOCK` (`ffi.rs:17-23`), a
  process-wide `static Mutex<()>` — matches `docs/plan/README.md`'s
  "Concurrency" row (cuJSON uses the default stream, no per-call state).
  `cuda_info()` (`ffi.rs:81-133`) checks `cujson_cuda_runtime_version()`
  then `cujson_device_count()`, mapping a negative return (a negated
  `cudaError_t`) to `Error::Cuda{code,message}` and a `0` count to
  `Error::NoDevice`, before listing devices via `cujson_device_name`
- `crates/cujson/src/error.rs`: top-level `Error` (`#[non_exhaustive]`)
  with `CudaNotCompiled`, `NoDevice`, `InvalidUtf8`, `Unbalanced`,
  `InputTooLarge{len,max}`, `EmptyInput`, `Cuda{code,message}`, `Internal`,
  `Io(io::Error)`, distinct from `tape::Error` (navigator/CPU-builder
  errors, unchanged from task 05)
- `crates/cujson/src/tape/storage.rs`: `TapeStorage::Pinned{alloc, ptr,
  len}` (`storage.rs:45-50`, `cfg(feature = "cuda")`) is a read-only slice
  into a pinned host allocation shared via `Arc<PinnedAlloc>`
  (`storage.rs:15-31`) between a `Tape`'s `structural` and `pair_pos`
  fields — `cujson_tape_free` (`PinnedAlloc::drop`, `storage.rs:33-37`)
  runs exactly once, when the last `Arc` clone drops. `TapeStorage` gets a
  blanket `unsafe impl Send`/`Sync` (`storage.rs:53-59`) justified by the
  pointer only ever being read and staying valid for as long as its `Arc`
  lives. `tape_from_ffi` (`storage.rs:143-163`, `pub(crate)`, `cfg(cuda)`)
  builds a `Tape` from a raw `cujson_sys::cujson_tape`, reading
  `raw.structural`/`raw.pair_pos` as two independent pointers into that one
  allocation (`cujson_capi.h`'s own field comments: `pair_pos` "points into
  the same allocation as structural") rather than computing an offset
  itself — `capi_standard.cu:62-65`/`capi_lines.cu:109-112` already hand
  back both pointers separately, so no `base + n + 1` arithmetic is needed
  on the Rust side
- `Tape::depth` is now a method, not a stored field (`storage.rs:99-124`):
  it walks `pair_pos` with a stack, pushing an index `i` whose
  `pair_pos[i] > i` (an opener) and popping when `i` reaches that pushed
  closer index, tracking max stack depth over real entries `1..len-1`. This
  needs no character classification and works identically for
  `TapeStorage::Owned` and `::Pinned`. Verified against the hand-worked
  `{"a":1,"b":[2,3]}` tape in `document.rs`'s tests (depth 2, matching the
  literal that used to be hand-written into that test's `Tape { depth: 2,
  .. }`, now computed instead of stated)
- `crates/cujson/src/tape/diff.rs` (`cfg(feature = "cpu-reference")`):
  `diff_tapes(input: &[u8], a: &Tape, b: &Tape) -> Option<TapeDiff>`
  compares `structural` at every index, then `pair_pos` only at indices
  `1..len-1` whose tape character (read via a private `tape_char` that
  mirrors `Document`'s `get_char`, `document.rs:74-90`) is `{` or `[` —
  `FORMAT.md` §3's undefined-slot exclusion. `Tape::depth()` is never
  compared (has no GPU counterpart, FORMAT.md §4). `TapeDiff{index, field,
  a, b, context}` implements `Display`, `context` holding up to 32 bytes of
  input around the mismatch's byte offset. `DiffField::{Structural,
  PairPos, Length}`. Four unit tests (`diff.rs:158-206`) cover: identical
  tapes → no diff, a corrupted structural entry → detected, a corrupted
  non-opener `pair_pos` slot → ignored, a corrupted opener `pair_pos` slot
  → detected
- `crates/cujson/src/lib.rs`'s `cpu` module (`cfg(feature =
  "cpu-reference")`, `lib.rs:180-198`) is the only place `build_tape_cpu`
  is reachable from outside the `tape` module — `cpu::parse(&[u8], Mode) ->
  Result<Document<'_>, tape::Error>` — kept separate from `parse`/
  `parse_lines` so nothing can call it while believing it's the GPU path
- `crates/cujson/tests/gpu.rs`, all `#[ignore = "requires GPU"]` (listed
  for task 10): `standard_fixture_matches_serde_json`,
  `lines_fixture_matches_serde_json`,
  `standard_fixture_tape_matches_cpu_reference`,
  `lines_fixture_tape_matches_cpu_reference`,
  `lines_multi_chunk_tape_matches_cpu_reference` (256-byte chunks, so it
  actually exercises `cujson_parse_lines`'s multi-chunk path, unlike the
  plain fixture test), `fixed_seed_corpus_tape_matches_cpu_reference` (300
  generated values via an in-file fixed-seed xorshift generator, avoiding a
  new `rand` dependency for one test file),
  `error_paths_then_valid_parse_still_works`,
  `repeated_invalid_parses_do_not_grow_device_memory` (best-effort,
  `nvidia-smi`-based approximation of task 10 step 6's authoritative
  check). Every parse in this file goes through the public `cujson::parse`/
  `parse_lines` API, so `GPU_LOCK` is held by construction — no test calls
  `cujson_sys` directly
- Non-ignored coverage of the "no CUDA driver" path, run in this
  GPU-less/driver-less container under `--features cuda`:
  `lib.rs`'s `tests_cuda_no_device` module (`cfg(all(test, feature =
  "cuda"))`) — `cuda_info_errors_without_a_driver` and
  `parse_errors_without_a_driver` both assert `Err(_)`, confirmed passing
  here (tier 2: compiled+linked with `cuda`, no GPU/driver present).
  `tests_no_cuda` (`cfg(all(test, not(feature = "cuda")))`) covers the
