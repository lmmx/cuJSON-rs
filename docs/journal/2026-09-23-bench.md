# 2026-09-23: cujson-bench, cuJSON vs simd-json on Wikidata claims

## Current State

- `crates/cujson-bench` (`publish = false`, workspace member) is a binary with subcommands `run` and `verify`; feature `cuda` forwards to `cujson/cuda`, and the `cpu-reference` feature of `cujson` is always on
- `data.rs` reads one string column (default `claims`) of a parquet file with the `parquet` crate, skips null, empty and raw-newline rows (counted and printed), and joins the rest as JSON Lines into batches of at most `--batch-mb` MiB
- `engines.rs` runs six engines per batch at two levels (`parse`, `walk`): `simd`, `simd-par`, `simd-buf`, `simd-buf-par` (`simd_json::to_borrowed_value`, or `to_borrowed_value_with_buffers`, over `split_mut` or rayon `par_split_mut` rows, on a per-run mutable copy of the batch, timed as phase `copy`) and `cujson`, `cujson-par` (`cujson::parse_lines`, then `Document::lines()` walked serially or collected and walked in rayon)
- `walk.rs` folds every node into a `u64`: tag, integer-or-float bits (`as_i64`, else `as_f64`; simd-json `U64` above `i64::MAX` folded as `f64`), hash of unescaped strings and keys, array length and order, and object entries combined with wrapping addition because `simd_json` objects iterate in hash order
- `run` prints median, min and max wall time over `--reps` (default 5, after `--warmup` 2), GB/s, rows/s, per-phase medians and peak RSS above the loaded corpus (`/proc/self/status` `VmHWM`, reset through `/proc/self/clear_refs`); `--json` prints one object per engine and level; a `walk` checksum that differs from the first engine's aborts the run
- `verify` compares per-row `walk` checksums of simd-json, `cujson::cpu::parse(.., Mode::Lines)` and, when a device is present, `cujson::parse_lines`, and exits non-zero on any mismatch
- `data/chunk_0-00283-of-00546.parquet` (92,039,060 bytes, SHA-256 `4c21bb31…9246e4`) is committed; `fetch.sh` downloads it from revision `064f404b…` of `philippesaade/wikidata`, the revision recorded in `~/lab/wikidata`'s `.cache/huggingface` metadata for the pipeline's own copies
- The file holds 1818 rows of `claims`, 233.4 MB as JSON Lines (mean 128,380 B per row, max 2,601,658 B), so one 256 MiB batch and one cuJSON chunk
- The current `main` of `philippesaade/wikidata` lists 7,449 files named `data/chunk_N.parquet` (959 GB), not the `chunk_N-XXXXX-of-XXXXX.parquet` names of the pipeline's 9,687 files, so `resolve/main/data/chunk_0-00283-of-00546.parquet` returns 404
- Two unit tests in `walk.rs` (`parsers_agree_on_edge_cases`, `checksum_detects_differences`) compare simd-json with the CPU-reference tape on numbers, escapes, nesting and key order, and check that value, key, array-order and number-type changes alter the checksum
- simd-json 0.17 returns `InvalidNumber` for the integer `123456789012345678901234567890` (beyond `u64`), where the cuJSON walker folds such a number through `as_f64`

## Verification tiers

- Tier 1 (container, no `cuda`): `cargo fmt --check`, `cargo clippy -p cujson-bench --all-targets -- -D warnings`, `cargo test -p cujson-bench` pass; `verify` on the committed file reports 1818 rows with 0 mismatching checksums between simd-json and the CPU-reference tape
- Tier 1 timings on the container's 20 threads over the committed file (medians of 3): `simd` parse 0.524 s (0.45 GB/s), `simd-par` parse 0.137 s (1.71 GB/s) of which 0.069 s is the `copy` phase, `simd-par` walk 0.144 s, `simd-buf-par` parse 0.142 s
- Tier 2 (`CUJSON_CUDA_ARCHS=86`, `--features cuda`): builds and passes clippy; `run --engines cujson` prints `unavailable (CUDA error 35 ...)` and exits without panicking in the container's driverless environment
- Tier 3: no `cuJSON` timing and no GPU-tape checksum agreement has been observed; `verify` and `run` with `--features cuda` are unrun on a GPU
