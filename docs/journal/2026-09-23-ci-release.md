# 2026-09-23: CI and release workflows

## Current State

- `.github/workflows/ci.yml` has a `check` job (ubuntu-latest, no container): `cargo fmt --all --check`, `cargo clippy --workspace -- -D warnings`, `cargo test --workspace`, then a conditional maturin build + pytest against `crates/cujson-py` gated on `hashFiles('crates/cujson-py/Cargo.toml') != ''` — currently false since that crate does not exist yet, so those two steps no-op until task 08 merges.
- `ci.yml` has a `cuda-compile` job, matrix `{cuda: ["12.8.1", "13.0.0"]}` in `nvidia/cuda:${{matrix.cuda}}-devel-ubuntu22.04` containers: installs rustup via `dtolnay/rust-toolchain@stable`, runs `cargo clippy --workspace --features cuda -- -D warnings`, `cargo build --workspace --features cuda`, `cargo test --workspace --features cujson/cuda`, then an `ldd`-based step that fails the job if `target/debug/cujson` links `libcudart` dynamically. The `12.8.1` leg sets `CUJSON_CUDA_ARCHS=80`; the `13.0.0` leg leaves it unset so the full default arch list (task plan README: 75,80,86,89,90,100,120 for CUDA 13) is exercised at least once.
- `.github/workflows/release.yml` triggers on `push: tags: ["v*.*.*"]` and `workflow_dispatch` with a `dry_run` boolean input (default `true`).
- `release.yml` `cli` job: matrix `cuda_major: [12, 13]` in the same `nvidia/cuda:*-devel-ubuntu22.04` containers, builds `cargo build --release -p cujson-cli --features cuda`, asserts no dynamic `libcudart` via `ldd`, packages `cujson-cu{12,13}-x86_64-unknown-linux-gnu.tar.gz`, uploads as a workflow artifact (`actions/upload-artifact@v4`).
- `release.yml` `wheel` job: matrix `cuda_major: [12, 13]` in `quay.io/pypa/manylinux_2_28_x86_64`, installs the CUDA toolkit via `dnf config-manager --add-repo https://developer.download.nvidia.com/compute/cuda/repos/rhel8/x86_64/cuda-rhel8.repo` then `dnf install cuda-nvcc-{12-8,13-0} cuda-cudart-devel-{12-8,13-0} cuda-cccl-{12-8,13-0}`, installs rustup and maturin, rewrites `crates/cujson-py/pyproject.toml`'s `name = "cujson"` to `cujson-cu{12,13}` with `sed`, runs `maturin build --release --features cuda -m crates/cujson-py/Cargo.toml`, then greps `auditwheel show` output for any `lib(cudart|cublas|curand|cufft|cusolver|cusparse|nvrtc|cuda)*` name and fails the job if one appears (libcuda is expected to be entirely absent, dlopen'd by the driver at runtime rather than bundled).
- `release.yml` `crate-package-check` job: runs `cargo package -p cujson-sys --allow-dirty --no-verify --list` and `... --no-verify`, then fails if the resulting `.crate` exceeds 10485760 bytes (crates.io's 10 MB limit).
